# Contributing

Use Node.js 22.17+, `npm ci`, and `npm run dev`. Submit a pull request describing the resulting behavior and validation; run `npm run check` and production-static Playwright checks when supported. Record unperformed device/browser checks honestly. Keep controls keyboard accessible, mark English passages within Odia pages with the appropriate language, preserve Unicode Odia and authorial line breaks, and avoid unnecessary services/dependencies.

The active implementation uses Next.js App Router static export into `out/`. Do not add backend APIs, server actions, middleware, accounts, or paid reading flows. Preserve existing reader data through IndexedDB upgrades. Shareable reading URLs and back/forward navigation must not silently replace saved progress for invalid locations. Offline downloads must be explicit and removable; fallback responses must use valid browser Response objects.

For book proposals, identify the author, exact edition, source URL, and separate work/edition rights evidence. Follow [the book contribution guide](docs/BOOK_CONTRIBUTION_GUIDE.md). Never label invented examples as authentic works. Correct text only with source evidence and record editorial changes. Every authentic line requires manual comparison against its lawful source and maintainer approval before publication.

Code and developer documentation contributions are MIT. Literature, fonts, and third-party artwork require separate rights. Keep complete OFL notices and font provenance; do not subset Indic glyphs or remove shaping tables casually. Noto Serif Oriya and Anek Odia compression reports verify font data, not physical-device appearance.

Public feedback contact: WhatsApp `+91 73816 99797`. The application opens a user-reviewed draft and does not send messages automatically. Public environment values are visible to everyone; never commit secrets. Keep `.env.local` ignored and the tracked `.env.production` limited to the public contact number. Private reading/bookmark/feedback data must not enter analytics.
